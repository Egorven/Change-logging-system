# Change-logging-system – система ведения журнала изменений

## Назначение

Change-logging-system – приложение для учёта проектов, версий, разработчиков и изменений в программных продуктах.

Консольная версия приложения (ПР3) дополнена веб-интерфейсом на Django (ПР5).

Приложение позволяет:

- добавление и удаление проектов;
- добавление и сортировка версий по дате выпуска;
- добавление записей об изменениях с указанием типа, автора и даты;
- форматирование записей журнала в человекочитаемый вид;
- фильтрация изменений по категории (добавлено / исправлено / удалено);
- сортировка изменений по дате;
- получение статистики по категориям изменений;
- добавление и просмотр списка разработчиков;
- экспорт данных проекта, его версий и изменений в JSON.

## Используемые технологии

* Python 3;
* Django 5.2 – веб-фреймворк;
* HTML – разметка веб-страниц;
* CSS и Bootstrap 5.3 – оформление страниц;
* pytest – автоматизированные тесты;
* flake8 – проверка качества кода.

## Целевая аудитория

Разработчики и менеджеры проектов, которым необходимо вести журнал изменений в программных продуктах и отслеживать версии.

## Предметная область

Основными объектами предметной области являются:
- **проект** — программный продукт, для которого ведётся журнал изменений;
- **версия** — выпуск проекта с определённой датой;
- **разработчик** — автор изменений;
- **изменение** — запись в журнале, связывающая проект, версию и разработчика.

Разработчик может добавлять записи об изменениях в определённую версию проекта. Каждое изменение имеет тип (добавлено, исправлено, удалено), описание, автора и дату.

## Основные сущности

### Project — проект

Объект `Project` представляет проект, для которого ведётся журнал изменений.

**Основные атрибуты:**
- `id` — уникальный идентификатор проекта;
- `name` — название проекта;
- `description` — описание проекта.

**Основные методы:**
- `__init__()` — конструктор объекта;
- `__str__()` — строковое представление проекта.

### Developer — разработчик

Объект `Developer` представляет автора изменений.

**Основные атрибуты:**
- `id` — уникальный идентификатор разработчика;
- `name` — имя разработчика;
- `role` — роль в проекте.

**Основные методы:**
- `__init__()` — конструктор объекта;
- `__str__()` — строковое представление разработчика;
- `from_data()` — создание объекта из словаря данных (декоратор `@classmethod`).

### Version — версия проекта

Объект `Version` представляет выпуск проекта.

**Основные атрибуты:**
- `id` — уникальный идентификатор версии;
- `name` — название версии (например, «1.0.0»);
- `release_date` — дата выпуска;
- `project` — объект `Project`, к которому относится версия.

**Основные методы:**
- `__init__()` — конструктор объекта;
- `__str__()` — строковое представление версии.

### Change — запись журнала изменений

Объект `Change` представляет запись об изменении в проекте.

**Основные атрибуты:**
- `id` — уникальный идентификатор записи;
- `type` — тип изменения (`added`, `fixed`, `removed`);
- `description` — описание изменения;
- `author` — имя автора;
- `date` — дата изменения;
- `project` — объект `Project`, к которому относится изменение;
- `version` — объект `Version`, к которому относится изменение;
- `developer` — объект `Developer`, автор изменения.

**Основные методы:**
- `__init__()` — конструктор объекта;
- `__str__()` — строковое представление записи;
- `format_entry()` — формирование человекочитаемой строки;
- `is_added()` — проверка, является ли изменение добавлением;
- `is_fixed()` — проверка, является ли изменение исправлением;
- `is_removed()` — проверка, является ли изменение удалением.

## Взаимодействие объектов

Объект `Change` связывает объекты `Project`, `Version` и `Developer`, храня ссылки на них, а не только их идентификаторы. Это позволяет напрямую обращаться к данным связанных объектов:

```python
change.project.name      # название проекта
change.version.name      # название версии
change.developer.name    # имя разработчика
```

Объект `Version` хранит ссылку на объект `Project`, к которому он относится:

```python
version.project.name     # название проекта версии
```

## Страницы веб-интерфейса

* `/` – главная страница: описание приложения и навигация (view-функция `index()`);
* `/projects/` – список проектов: объекты `Project` из `data/project.json` (view-функция `projects()`);
* `/projects/<int:project_id>/` – страница проекта с версиями (view-функция `project_detail()`);
* `/changes/` – список изменений: объекты `Change` из `data/changes.json` (view-функция `changes()`);
* `/changes/<int:change_id>/` – страница изменения (view-функция `change_detail()`).

Если проект или изменение с указанным идентификатором не найдено, соответствующая страница возвращает код статуса 404.

## Основные операции

### Используется в веб-интерфейсе (ПР5)

* просмотр списка проектов;
* просмотр информации о проекте и его версиях;
* просмотр списка изменений;
* просмотр информации об изменении.

### Отложено до следующих работ

Эти операции реализованы в ПР3 и работают в консольной версии. В веб-интерфейсе они появятся, когда будут добавлены формы и POST-запросы:

* добавление проекта;
* удаление проекта;
* добавление версии;
* сортировка версий;
* добавление изменения;
* фильтрация изменений по типу;
* сортировка изменений;
* получение статистики по категориям;
* добавление разработчика.

## Хранение данных

Данные приложения хранятся в JSON-файлах:

* `data/project.json`;
* `data/version.json`;
* `data/changes.json`;
* `data/developer.json`.

При загрузке данные из JSON преобразуются в объекты `Project`, `Version`, `Change` и `Developer`. При сохранении объекты преобразуются в данные JSON.

Для связи изменения с проектом, версией и разработчиком в `changes.json` используются их идентификаторы `project_id`, `version_id` и `developer_id`.

## Назначение модулей

### `main.py`
Консольная версия приложения (сохранена с ПР3).
Отвечает за:
* запуск консольного приложения;
* отображение меню;
* получение данных от пользователя;
* организацию пользовательских сценариев.

### `changelog/`
Пакет настроек Django-проекта:
* `settings.py` – настройки проекта;
* `urls.py` – маршрутизация верхнего уровня;
* `asgi.py`, `wsgi.py` – точки взаимодействия с сервером.

### `homepage/`
Django-приложение, отвечающее за главную страницу:
* `views.py` – функция `page()` (общий HTML-каркас), view-функции `index()` и `page_not_found()`;
* `urls.py` – маршрут главной страницы.

Функция `page()` размещена здесь, потому что главная страница задаёт общий вид всех остальных страниц – она точка входа в проект. Остальные приложения импортируют её.

### `projects/`
Django-приложение, отвечающее за проекты и версии:
* `views.py` – view-функции `projects()` и `project_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

### `changes/`
Django-приложение, отвечающее за изменения:
* `views.py` – view-функции `changes()` и `change_detail()`;
* `urls.py` – маршруты приложения;
* `models.py` – Django-модели (заполняется в следующих работах).

### `models/`
Классы предметной области и функции работы с ними (пакет ПР3):
* `project.py` – класс `Project` и функции работы с проектами;
* `developer.py` – класс `Developer` и функции работы с разработчиками;
* `version.py` – класс `Version` и функции работы с версиями;
* `change.py` – класс `Change` и функции работы с изменениями.

### `storage.py`
Отвечает за загрузку и сохранение данных.
Выполняет преобразование:
* JSON → объекты Python;
* объекты Python → JSON.

### `utils.py`
Содержит вспомогательные функции консольного ввода:
* `input_int()` – безопасный ввод целого числа;
* `input_date()` – безопасный ввод даты;
* `input_text()` – безопасный ввод текста.

### `tests/`
Содержит автоматизированные тесты проекта.

## Запуск приложения

Веб-версия (Django):
